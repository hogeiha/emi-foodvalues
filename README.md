# EMI Food Values

一个 EMI 附属模组，给食物加两个能看数值的类别：饥饿值和实际饱和度一眼可见，并且按数值排好序。

- Minecraft 1.19.2 / Forge 43.x / Java 17
- 客户端模组，服务端不需要装
- 需要 EMI（Forge 1.19.2 的 1.1.x，开发时用的是 `1.1.24+1.19.2`）

## 饥饿值和饱和度是什么

这两个经常被混着叫，其实是不同的东西：

| | 说明 | 例子 |
| --- | --- | --- |
| 饥饿值（hunger / nutrition，口语也叫饱食度） | 吃完立刻恢复的鸡腿数量 | 金胡萝卜 6、熟牛排 8 |
| 饱和度（saturation） | 隐藏值，藏在饥饿条后面的缓冲；饥饿条满的时候先消耗它，所以越高越"耐饿"，不会马上掉饥饿条 | 金胡萝卜 14.4、熟牛排 12.8 |

实际饱和度 = `饥饿值 × saturationModifier × 2`，模组里显示的就是这个算好的结果。
两者不成正比：金胡萝卜饥饿值只有 6，但饱和度 14.4，比饥饿值 8 的熟牛排（12.8）更耐饿 —— 所以要分开看。

## 内容

| 类别 | 排序 |
| --- | --- |
| 食物数值（按饱和度） | 实际饱和度从高到低 |
| 食物数值（按饥饿值） | 饥饿值从高到低 |

每个条目显示物品、名字、`饥饿值：x`、`饱和度：y`。

## 三种搜索方式

在 EMI 搜索栏里输入下面三组关键词，互不干扰：

| 关键词 | 作用 |
| --- | --- |
| `食物` | 所有可食用物品 |
| `饥饿值…` | 只按实际回复的饥饿值筛（`饱食度…` 是同义词，写法一样） |
| `饱和度…` | 只按隐藏的饱和度筛 |

每组的写法是 `值+数字`（正好）、`值=数字`（同上，带等号也行）、`值数字+`（至少）：

| 输入 | 结果 |
| --- | --- |
| `饥饿值8` 或 `饥饿值=8` | 饥饿值正好 8 的食物（熟牛排、金苹果等） |
| `饥饿值6+` | 饥饿值 ≥ 6（档位还有 `4+`、`8+`） |
| `饱和度14` 或 `饱和度=14` | 饱和度为 14 点多的食物（取整数部分，例如金胡萝卜 14.4） |
| `饱和度10+` | 饱和度 ≥ 10（档位还有 `5+`、`15+`） |

几点说明：

- 只打关键词（`饥饿值`、`饱和度`）时，因为每个食物都登记了对应别名，结果就是全部食物；要过滤记得带上数字。
- EMI 的别名是**子串匹配**，所以 `饱和度1` 会连带 `饱和度14`、`饱和度10+` 一起出现，数字写全就精确了。
- 可以叠加，空格在 EMI 里是 AND，例如 `食物 饱和度10+`、`饥饿值6+ 饱和度10+`。

**看排行榜**：按 `R` 打开配方页，顶栏的类别栏里选「食物数值（按饱和度）」或「食物数值（按饥饿值）」，进去就是按数值排好序的列表。
鼠标停在食物上按 `U`，用途列表里也能看到属于这两个类别的条目。

## 安装

把 jar 放进 `mods` 即可。启动后日志里会有类似的一行：

```
[emifoodvalues/]: Registered N food entries in 2 EMI categories
```

`N` 是当前整合包里食物数量 × 2。

## 编译

Java 17 + Gradle 8.1+（仓库自带的 wrapper 是 8.5）。

```
gradlew.bat build     # Windows
./gradlew build       # Linux / macOS
```

产物在 `build/libs/`。发布请用这个 jar，ForgeGradle 打包时已经做过重映射，直接拿 `build/classes` 里的 class 在正式环境跑不起来。

EMI 的 maven（`repo.sleeping.town`）国内偶尔连不上，`build.gradle` 里已经把这个仓库限定为只解析 `dev.emi`，避免拖慢 Forge 依赖；实在连不上可以用 `-PemiLocalRepo=<本地 maven 目录>` 指定一份本地副本。

## 开发备注

- Forge 下 EMI 通过 `@EmiEntrypoint` 注解扫描插件，不需要在 `mods.toml` 里登记。
- 类别名是 `emi.category.<命名空间>.<路径>`，要和语言文件的键对应。
- 排序用 `EmiRecipeCategory` 的第 4 个参数（比较器），EMI 烘焙配方表时会用它排序。
- 搜索别名用 `EmiRegistry#addAlias`，EMI 内部会把别名丢进子串搜索索引；同一个物品登记多条别名是正常用法。

## 已知限制

- 搜索栏不支持 `饱和度>5` 这种表达式写法，EMI 的搜索解析器不认；用 `饱和度5+` 代替。
- 一个类别里条目比较多，第一次打开会稍微卡一下。
