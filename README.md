# EMI Food Values

一个 EMI 附属模组，给食物加两个能看数值的类别：饱食度和实际饱和度一眼可见，并且按数值排好序。

- Minecraft 1.19.2 / Forge 43.x / Java 17
- 客户端模组，服务端不需要装
- 需要 EMI（Forge 1.19.2 的 1.1.x，开发时用的是 `1.1.24+1.19.2`）

## 饱食度和饱和度是什么

这两个经常被混着叫，其实是不同的东西：

| | 说明 | 例子 |
| --- | --- | --- |
| 饱食度（hunger / nutrition） | 吃完立刻恢复的鸡腿数量 | 金胡萝卜 6、熟牛排 8 |
| 饱和度（saturation） | 藏在饥饿条后面的额外缓冲，吃饱时先消耗它，所以越高越"耐饿"，不会马上掉饥饿条 | 金胡萝卜 14.4、熟牛排 12.8 |

实际饱和度 = `饱食度 × saturationModifier × 2`，模组里显示的就是这个算好的结果。
所以会出现"饱食度低但饱和度很高"的食物（金胡萝卜就是典型），这也是两个值要分开看的原因。

## 内容

| 类别 | 排序 |
| --- | --- |
| 食物数值（按饱和度） | 实际饱和度从高到低 |
| 食物数值（按饱食度） | 饱食度从高到低 |

每个条目显示物品、名字、`饱食度：x`、`饱和度：y`。

## 用法

**找全部食物**

在 EMI 搜索栏输入 `食物`（英文语言 `food`），列出所有能吃的。
可以叠加关键词，例如 `食物 金`（空格在 EMI 里是 AND）。

**按数值搜**

两个值分开搜，格式是 `值 = 数字`（正好这个值）和 `值 数字+`（至少这个值）：

| 输入 | 结果 |
| --- | --- |
| `饱食度=8` | 饱食度正好 8 的食物 |
| `饱食度6+` | 饱食度 ≥ 6 的食物（另有 `饱食度4+`、`饱食度8+`） |
| `饱和度=14` | 饱和度为 14 点多的食物（取整数部分） |
| `饱和度10+` | 饱和度 ≥ 10 的食物（另有 `饱和度5+`、`饱和度15+`） |

EMI 的别名是子串匹配，所以输入 `饱和度1` 也会把 `饱和度=14`、`饱和度10+` 一起带出来；
想精确一点就把 `=` 或 `+` 一起打上。多个词可以组合，例如 `食物 饱和度10+`。

**看排行榜**

按 `R` 打开配方页，顶栏的类别栏里选「食物数值（按饱和度）」或「食物数值（按饱食度）」，进去就是按数值排好序的列表。
鼠标停在食物上按 `U`，用途列表里也能看到属于这两个类别的条目。

## 安装

把 jar 放进 `mods` 即可。启动后日志里会有类似的一行：

```
[emifoodvalues/]: Registered N food entries in 2 EMI categories
```

`N` 是当前整合包里食物数量 × 2。

## 编译

Java 17 + Gradle 8.1+（仓库自带的 wrapper 是 8.5）。

```
gradlew.bat build     # Windows
./gradlew build       # Linux / macOS
```

产物在 `build/libs/`。发布请用这个 jar，ForgeGradle 打包时已经做过重映射，直接拿 `build/classes` 里的 class 在正式环境跑不起来。

EMI 的 maven（`repo.sleeping.town`）国内偶尔连不上，`build.gradle` 里已经把这个仓库限定为只解析 `dev.emi`，避免拖慢 Forge 依赖；实在连不上可以用 `-PemiLocalRepo=<本地 maven 目录>` 指定一份本地副本。

## 开发备注

- Forge 下 EMI 通过 `@EmiEntrypoint` 注解扫描插件，不需要在 `mods.toml` 里登记。
- 类别名是 `emi.category.<命名空间>.<路径>`，要和语言文件的键对应。
- 排序用 `EmiRecipeCategory` 的第 4 个参数（比较器），EMI 烘焙配方表时会用它排序。
- 搜索别名用 `EmiRegistry#addAlias`，EMI 内部会把别名丢进子串搜索索引。

## 已知限制

- 搜索栏不支持 `饱和度>5` 这种表达式写法，EMI 的搜索解析器不认；用上面的 `饱和度5+` 代替。
- 一个类别里条目比较多，第一次打开会稍微卡一下。
